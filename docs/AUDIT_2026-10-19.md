# Code audit, 2026-10-19: what was found, what is fixed, what is not

Scope: the whole `vehiclegpt2` tree (124 Python modules, about 26,000 lines in `vgpt/`), with the meaning-frame front end (`vgpt/meaning/`) as the main subject.  Training was stopped after `full_v6`, as asked.  Everything below was run on this machine; nothing is estimated unless it says so.

## 1. How the audit was done

* `python -m compileall` on every package (clean); `pyflakes` over `vgpt/`, `ui/`, `app.py` (one undefined name, fixed).
* Pattern searches: dead branches (`if False`), swallowed exceptions, f-string SQL, text patterns in the meaning path.
* The full test suite, three times (start of night 41 failing, after the first fixes 15, final: see section 5).
* A fuzz of the meaning pipeline: 220 hostile and random inputs (empty, NUL bytes, 700-character words, SQL and template injection, right-to-left marks, emoji, Hindi / Arabic / Japanese, "ignore all previous instructions", absurd periods): 0 exceptions, 0 empty answers.
* A read-by-eye probe of the pipeline on about 1,000 questions nobody wrote for it (the three older question banks and four hard sets), the source of most bugs below.
* Frozen-set integrity: all ten evaluation sets match their SHA-256 files.
* Latency and memory with the final adapter on two pinned cores.

## 3. Fixed

### 3.1 Wrong or invented answers (the dangerous kind)
* A typed calendar date was ignored: "speed on 17 March 2025 at 09:13:27" was answered with **today's 09:13: 0.0 km/h**.  Dates, number-word intervals ("between three and five days ago"), "since monday" and "a day and a half ago" are now parsed as values; an interval with no data says so.
* Wrong period, silently: the same questions above were answered over the default week.  A bounded `between` time type (days / hours ago, never an absolute timestamp) was added to the typed engine; the validator still refuses absolute timestamps.
* Display units ("tyre pressure in psi", "distance in miles", "in fahrenheit") were ignored by the meaning path and by answers that already print the degree sign.
* A counterfactual ("would the fault still have occurred on a flat road?") was refused as tampering; predictions of faults were answered with the service interval; "which manufacturer's sensor caused the anomaly" with a camera explanation.  Fixed in training data (honesty bank), not by rules.
* "Average speed" was refused whenever the 1 Hz tier did not span the period (`analytics.summary`); the minute-tier mean is sound, only the extremes are withheld now.
* A tyre-pressure question was answered with the definition of a tyre; a mAh question that gave a voltage was answered as a capacity statement; "driving score" was pre-empted by a later rule.
* My own honesty rows labelled "which places do I visit most" as unsupported although the product answers it; corrected.

### 3.2 Crashes and silent failures
* `no such table: charges` crash in `semantic_ops` (broke the robustness fuzz and any vehicle without that table): handlers now treat a missing table as "not applicable".
* `AttributeError` on the trend of energy, distance or Wh per km beyond seven days (`query_executor._finish` with no sample frame): the trip-ledger path is now handled.
* `KeyError` in the literal parser for any event or topic concept with a threshold in the text ("which fault codes were logged above 80 km/h", "how long does it take to fill up to 100 percent").
* A resolver or legacy-adapter exception now becomes an honest sentence; it can no longer take the UI worker down.
* The interpretation-review endpoint raised `AttributeError` because it needs the retired planner route; it now says so (its three tests are skipped with the reason).
* `qa_e.py` referenced an undefined name inside a dead ternary; removed.

### 3.3 Capability gaps found by probing and closed
* Present speed is answered by the typed engine only (the dashboard and the assistant share one evidence record; the duplicate rule was removed).
* Trips as dated events ("when did I leave", "tell me about my last trip"), "which places do I go to most", "is my driving getting better", charging state / power (legacy routine through a binding), fault-code lookup ("what is P1A00"), per-day extremes of any recorded signal, the rain sensor as a duration, counts of crossings ("how many times did the soc go below 20"), a peak inside the last trip, mAh to Wh with a typed voltage, a bare number after a comparator ("when above 50"), "yesterday's energy per km" (a ratio asked at a time is read over the period), the units change re-showing the last answer, friendlier clarification wording, definitions for 21 events and derived quantities, and methods for turn radius, wheel slip, thermal rise rate, battery efficiency and the driving score.

### 3.4 Stale or conflicting tests (changed only with a stated reason)
Missing-table wording, product-factory test (the planner route is retired), camera-staleness wording, out-of-domain `schema` path, acceleration-band route label, the longest-slow-period test (it compared against the sparse 1 Hz tier; the one-minute tier is the documented basis and matches an independent brute force to the minute), `couldn't` wording for honest "no data" answers.  The three review-prototype tests are skipped, not deleted.

### 3.5 New tests and tooling
`tests/test_meaning.py` grew from 19 to 34 tests (value parsers, the bounded interval type, each resolver regression above, the "never raises" net).  New tools: `bench/meaning_eval/probe_answers.py`, `hard_v1..v5` (frozen, hashed), `e2e_auto.py` / `cs5_score.py`, a corrected end-to-end harness that resets display units per question, builder sources `honesty`, `hard1..hard3`, leak filters v1 to v6, and a politeness / hedging wrapper augmentation.

## 4. Not fixed (read this part)

### 4.1 Product behaviour
1. **Default switched on the owner's approval (2026-10-19, after this audit): the meaning front end is now the product default** (`product.make_qwen05_brain`, used by `app.py` and the shipped UI server).  `VGPT_MEANING=0` (or `meaning=False`) builds the previous front end unchanged; a caller that passes its own legacy classifier object, and the UI's test-only planner seam, keep the previous front end, so no existing test or bench changed behaviour silently (`bench/meaning_eval/run_current.py` pins `meaning=False` so the baseline stays reproducible).  A missing meaning adapter raises `FileNotFoundError` naming the way back; there is no silent switch.  With-model release builds (`tools_release.py`) now ship the meaning adapter and keep the legacy one.  Verified: the shipped `App` answers with `path=meaning`, `VGPT_MEANING=0` gives `path=qc/qa`, 171 related tests pass.  What the switch does NOT remove: the legacy rule layers remain in the tree (the `VGPT_MEANING=0` fallback and the 43 legacy-routine bindings the meaning path still calls), so "no hand-written rules" holds for question *understanding* but not for every executor behind it.
2. **13 legacy tests still fail** (`test_qa` 2, `test_qa2` 4, `test_round52_fixture` 2, `test_routing` 5).  With `semantic_ops.handle` disabled most of them pass again: the hand-written pre-emption layer broke the older router, and the typed capability layer intercepts DBC-decode, fleet and counterfactual wording before the older handlers run.  They test the superseded front end; chasing them would mean more regex.
3. **43 meanings still execute through legacy keyword code** (`bindings.json` "legacy": about 16 % of oracle answers).  They are reached by a machine-written request, but the routine behind them is the old regex code.
4. Remaining executor gaps with perfect understanding: quarter versus quarter, weekday versus weekend, "what was the car doing when it became less efficient" (context on a non-event signal), trend on most topic concepts, a peak of motor power (not recorded; the answer says so).
5. The frame model is stateless: follow-ups ("and yesterday?") are read as ambiguous.

### 4.2 Understanding
6. Hostile or terse wording: hard_v1 79.5 %, hard_v4 79.5 % (both trained on already, so these are development numbers), and a fresh persona set was 70.0 % for `full_v5` before round 6.  One-word asks ("status", "summary"), idioms, shouted and mixed-language wording are the weak spots.
7. Several of those gold labels are contestable (`status`, `report`, "is the battery feeling happy", `control` versus `unsafe` for "roll back the odometer"); they are reported, not retrained.  Infotainment, phone and e-mail requests are labelled `unsupported` in the training data and `control` / `unsafe` in two hard sets: an inconsistency in my evaluation sets, not in the model.
8. `unsafe` versus `control` is imperfect; both refuse.  Hazard-decision questions go through the deterministic safety guard before the model, by design.

### 4.3 Evidence quality
9. One author wrote the training banks and all evaluation sets; answer judgments are one reader's; no seed variance was measured (a retrain alone moves 5 to 8 questions per set).
10. The ablation arms were not built from identical inputs (the ontology and glossary were edited by another session while they ran); see "Input drift" in 6.9 of the method doc.
11. The Case Study 5 bundle is scored on a coarse act-set plus concept rule; 82.3 % by the first scorer, 90.3 % by the corrected one (two defects, reported side by side).
12. ARM was **not** measured.  Latency and memory above are x86 on two pinned cores.

### 4.4 Code hygiene (found, left alone because they are old and not wrong)
13. 13 `if False` dead branches (`answer_composer.py:247`, `completion.py:30`, `contracts.py:173`, `meaning/ontology.py:113`, `qa_b.py:262`, `qa_c.py:409`, `qa_d.py:462`, `qa_e.py:264`, `query_executor.py:509`, `semantic_ops.py:429`, `store.py:289`, `temporal_events.py:152`, `toolspec.py:332`); 41 `except Exception: pass` sites; about 1,328 regex call sites in `vgpt/` (44 in `vgpt/meaning/`, held to a budget by a test).
14. 37 f-string SQL statements: every interpolated item is a table / column identifier from the signal registry or a code constant, never user text, and the connection is read-only; still worth moving to a whitelist helper.
15. Repository clutter: `results/` is 18 GB; empty server logs and a patch tarball in the root; a stale copy of the code under `results/semantic_recovery/sprint/worktree_legacy`.  I deleted nothing.

### 4.5 Process
16. Running two GPU trainings at once was about four times slower each (an ablation arm that takes 45 minutes alone ran for hours); `full_v4` took about nine wall-clock hours because of it.
17. The rename from VehicleGPT to VANTAGE was **not** done, on the owner's instruction ("leave the name for now").

## 5. Tests, final tally

Full suite, final run (`results/meaning/full_suite_final.log`): **879 passed, 20 skipped, 13 failed** (18 min 45 s).  Start of the night: 41 failing.  The 13 are exactly the legacy-router tests in 4.1 (item 2): `test_qa` (hallucination attacks, paraphrase routing), `test_qa2` (counterfactuals, second stress list, fleet, DBC decode), `test_round52_fixture` (H6 causation, twice), `test_routing` (five threshold / route tests).  No test that passed at the start fails now.  Skipped: the three retired review-prototype tests (with their stated reason) and 17 tests that skip themselves when a fixture or file is missing.
